# 山姆代购与小区团购管理

React + Node + SQLite 的轻量团购系统。商品只在飞书编辑，由后台手动同步到数据库；顾客浏览、下单、查询和后台统计读取数据库。订单在网页后台维护，按小区和期次手动同步回飞书，供统计采买。付款确认以后独立加入。

## 启动

需要 Node 24 或更高版本、npm，以及已获得多维表格读写授权的 lark-cli 用户身份。

```sh
npm ci
# 尚无飞书商品库时先执行；已有项目复用配置。
npm run setup:feishu
npm run setup:admin
npm run build
npm start
```

后台入口：<http://127.0.0.1:3001/admin>。初始密码首次启动时生成，保存在 `.data/admin-initial-password.txt`，不会通过网页接口返回。可在 `.env` 配置至少 8 字符的 `ADMIN_PASSWORD`，重启后生效。后台会话 Cookie 为 HttpOnly，重启后需重新登录。

开发模式：`npm run dev`。前端和 API 共用 3001 端口。验证：`npm test`。

旧版第一次启动会先备份配置与提交日志，读取飞书商品、原期次和已完整确认订单，一次性导入 `.data/orders.sqlite`，保留旧链接。存在未确认旧提交或不完整飞书订单时停止迁移，要求先核查；之后启动直接读数据库。

## 每次团购怎么操作

1. 在飞书商品表维护商品 ID、名称、规格、单位、价格、分类、在售和排序。
2. 后台“商品库”点击“从飞书同步商品”，确认同步结果。
3. 在“团购期次”选择小区或群，首次可新增小区。“新建一期”自动接着编号第 1、2、3 期，默认带入当前在售商品，可调整范围并填写截止、取货说明。
4. 复制本期专属链接或下载二维码，发到对应群。顾客页面自动显示小区和期次。
5. 打开该期订单，按商品查看采购汇总，按手机号查看分货名单；可改数量、处理状态或取消某件商品。
6. 点击“同步本期订单到飞书”。再次修改后显示待同步，重新同步更新同一明细，不产生重复订单。

同一手机号仅在同一期归为同一顾客，每次新提交表示补单追加，重复提交编号不会多下单。购物车按期次独立保存。整单通过数据库事务保存后立即显示成功，查询无需等待飞书。

删除商品项使用“已取消”状态保留同步关系；取消和缺货排除在有效采购数量与金额外。停止收集或达到截止时间后禁止新下单，仍允许查询。

## 飞书配置

后台“飞书配置”会带入当前多维表格来源。粘贴飞书多维表格的 Base 链接，点击“读取数据表”，选择商品表与订单表，再检查连接并保存。也可在高级设置中填写 Base token 和数据表 ID。配置保存到 SQLite，立即供后续同步使用，重启后保留。

连接检查读取多维表格和字段结构，验证商品必需列、订单同步列及状态选项；读取成功不代表已经验证写入权限。飞书用户授权继续使用运行服务器上的 lark-cli，网页不接收应用密钥或访问令牌。授权失效时在服务器重新授权，回来检查连接。

保存配置不会自动导入商品或写入订单。更换商品来源后，到“商品库”手动同步；商品 ID 必须继续代表同一商品。更换订单导出目标会把已有明细标为待同步，下一次手动同步按固定明细编号核对，旧飞书表保留。如果旧目标还有无法确认的写入，系统要求先完成核查再切换。同步进行期间不能更换配置。

需要补齐新版订单同步字段时，`npm run setup:admin` 使用数据库中的当前配置。新来源仍需符合现有商品和订单字段结构；页面会列出缺失或类型不兼容的字段，检查失败不覆盖当前配置。

## 同步规则

商品 ID 是固定匹配键，也用于图片地址。更换 ID 表示另一个商品。同步分页读取完整数据，校验重复编号、必填内容和价格后才提交，失败保留原数据。飞书中消失的商品在数据库标记停售，保留已有订单关联。

名称、规格和价格采用最近同步的当前值。同步新价格后，已有订单金额随当前价格更新，不保存历史价格；相关订单会重新变为待同步。金额不包含配送费或代购费。

订单数据库为准，修改统一在网页后台进行；飞书用于同步后的统计、采购。每条明细有固定编号，重复同步按编号更新。新增请求结果不明确时先对账，不盲目再次创建；部分失败保留待同步。同步期间又编辑的明细不会被误标已同步。采购前请确认本期没有遗漏的待同步项。

飞书导出携带小区、期次、当前商品资料、单价与金额。后台专用视图使用同步字段统计，避免未同步的飞书价格与网页金额混用。当前下单成功只表示清单已保存，付款以后独立确认。

## 手机、分享与图片

在 `.env` 设置 `HOST=0.0.0.0` 后重启。手机连接同一 Wi-Fi，通过电脑局域网 IPv4 访问，例如 `http://192.168.1.100:3001/admin`。手机不能用电脑的 `127.0.0.1`，IP 可能随网络变化。

局域网监听时分享链接和二维码自动使用本机 IPv4。公网部署请配置 `PUBLIC_BASE_URL=https://你的域名`。公网部署、HTTPS 与微信实机兼容需要在可达地址下另外验证。

图片按商品 ID 匹配，默认示意图地址为 `/images/{id}/cover.svg`。更换文件服务器时，在 `.env` 设置 `IMAGE_URL_TEMPLATE=https://你的文件服务器/products/{id}/cover.jpg` 后重启。缺图使用占位图。演示商品、报价和示意图仅供测试，正式使用前请替换。

## 备份与维护

SQLite 保存实际订单、小区、期次和同步状态，需要保留整个数据目录。服务使用单个 Node 进程，并通过运行锁阻止同目录重复启动。

```sh
# 在线一致性备份数据库，并复制配置与后台密码文件。
npm run backup
# 可指定备份目录。
npm run backup -- /absolute/path/to/private-backup
```

默认备份在 `.data/backups`，含联系方式和后台密码，请保持私有。恢复时先停止服务并保留当前数据，建议把备份数据库及配置放到新的私有目录，使用 `DATA_DIR` 指向该目录后启动，避免混入旧 WAL 文件。建议采购前与集中改单后做一次备份。

环境配置参考 `.env.example`：`DATA_DIR`、`LARK_CLI_BIN`、`ADMIN_PASSWORD`、`PUBLIC_BASE_URL`。飞书固定使用用户身份，浏览器不接触 CLI 授权或凭证。数据库访问不依赖飞书在线，授权失效仅影响手动同步。

```sh
lark-cli auth status --json --verify
lark-cli auth login --help
```

反向代理时配置 `TRUSTED_PROXY_IPS=127.0.0.1,::1`，代理须正确处理转发地址和协议。默认不信任任意转发头。不要公开 `.data`、`.env` 或用户授权文件。

旧提交日志及维护脚本保留用于迁移核查；新一期通过后台建立。验收记录和含实际联系方式的数据保存在本地，不进入公开仓库。

## GitHub Actions 与服务器部署

CI 在 main 推送和 Pull Request 上运行 Node 24 的测试、前端构建和发布包检查。发布包只包含运行代码、前端产物、维护脚本及部署模板，排除数据库、授权、环境文件和本地验收资料。

服务器采用独立 Node 24、systemd 单进程和 Nginx HTTPS。目录约定：

- `/srv/apps/sam-group-buy/current`：指向当前版本。
- `releases/<commit>`：编译包及生产依赖。
- `shared/data`：SQLite 和后台密码，部署不会替换。
- `shared/.env`：环境变量，权限 600。
- `shared/home`：服务用户的飞书 CLI 配置与授权，保持私有。
- `shared/backups`：部署前的一致性数据库备份。
- `runtime/node`、`runtime/bin/lark-cli`：独立运行环境。

首次配置由服务器管理员完成：安装 Node 24 与 lark-cli、新建 `sam-group-buy` 服务用户、放入私有数据和环境文件，安装 `ops/sam-group-buy.service`，按 `ops/nginx.conf.example` 配置域名与证书。仅给部署用户重启及查询这一项 systemd 服务的 sudo 权限；GitHub 使用独立部署 SSH 密钥。

`production` GitHub environment 使用这些 Secrets：`DEPLOY_HOST`、`DEPLOY_PORT`（通常 22）、`DEPLOY_USER`、`DEPLOY_SSH_KEY`、`DEPLOY_KNOWN_HOSTS`。主机密钥须在可信 SSH 连接核对，不能关闭主机校验。Repository Variables：`DEPLOY_PATH`（默认上述目录）、`DEPLOY_ENABLED=true`（开启 main 推送自动部署）。未开启自动部署时仍可手动运行 `Deploy production`，仅 main 可部署。

部署会重新测试和构建，校验发布包与逐文件 SHA256，安装生产依赖，再备份当前数据库、切换版本、重启并检查本地健康接口。健康检查失败时恢复前一版本；保留当前、前一版本与最近一个版本。共享业务数据始终独立，代码回退不会自动回退数据库。

`npm run package:release` 生成 `.artifacts/sam-group-buy-<commit>.tar.gz` 和相应 manifest。维护环境参考 `.env.example`；生产设置 `HOST=127.0.0.1`、`DATA_DIR=/srv/apps/sam-group-buy/shared/data`、`PUBLIC_BASE_URL=https://你的域名`、`TRUSTED_PROXY_IPS=127.0.0.1,::1` 和 `LARK_CLI_BIN=/srv/apps/sam-group-buy/runtime/bin/lark-cli`。

飞书重新授权应在服务用户身份下执行 CLI，保证网页后台与命令行读取同一份配置；OAuth 链接及二维码只供本人操作，不写入公开仓库或 Actions 日志。
