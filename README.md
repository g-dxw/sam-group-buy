# 山姆代购与小区团购管理

React + Node + SQLite 的轻量团购系统。后台查询山姆商品，勾选后直接加入本地商品库；商品、期次和订单都在网页后台管理。飞书作为手动备份和订单导出目标，商品同步方向为本地 → 飞书，不再从飞书覆盖本地商品。付款确认以后独立加入。

## 启动

需要 Node 24 或更高版本和 npm。山姆查询与本地商品管理无需飞书；启用飞书备份时需要服务器上的 lark-cli 用户身份和目标多维表格读写授权。

```sh
npm ci
npm run build
npm start
```

后台入口：<http://127.0.0.1:3001/admin>。初始密码首次启动时生成，保存在 `.data/admin-initial-password.txt`，不会通过网页接口返回。可在 `.env` 配置至少 8 字符的 `ADMIN_PASSWORD`，重启后生效。后台会话 Cookie 为 HttpOnly，重启后需重新登录。

顾客首页：<http://127.0.0.1:3001/>，列出所有正在收集、尚未截单且未删除的团购期次。顾客选择一期进入商品页；只有一期时也保留列表。原来的 `/b/团购编号` 链接继续直接进入该期，已截单期次仍可查询订单。商品页的“全部团购”可返回首页重新选择。

开发模式：`npm run dev`。前端和 API 共用 3001 端口。验证：`npm test`。

旧版第一次启动会先备份配置与提交日志，读取飞书商品、原期次和已完整确认订单，一次性导入 `.data/orders.sqlite`，保留旧链接。存在未确认旧提交或不完整飞书订单时停止迁移，要求先核查；之后启动直接读数据库。

## 每次团购怎么操作

1. 后台“山姆选品”选择城市和门店，可直接点官方榜单浏览商品，或切换到“搜索商品”输入关键词，查看图片与销售价格，勾选后点击“加入商品库”。可分页选择，查询结果在服务器保存 30 分钟，过期或重启后需重新查询。
2. 在“商品库”核对名称、规格、单位和售价，再上架。分类暂时不在界面展示。上架保存商品的销售状态；如果期次已经建立，新商品还要到“团购期次 → 编辑本期 → 本期商品”加入该期，保存设置后顾客页才会展示。可用“追加新上架商品”带入新商品并保留原选择。新商品默认待上架；重复选同一山姆 SPU 只跳过，不覆盖已有售价、图片或上架状态。需要留存到飞书时点击“同步到飞书备份”。
3. 在“团购期次”选择小区或群，首次可新增小区。“新建一期”自动接着编号第 1、2、3 期，默认带入当前在售商品，可调整范围并填写截止、取货说明。在“本期采购门店”选定城市和门店，保存后开启顾客自选；清空门店关闭自选，已有推荐商品仍可下单。
4. 复制本期专属链接或下载二维码，发到对应群。顾客页面自动显示小区和期次。
5. 打开该期订单，按商品查看采购汇总，按手机号查看分货名单；可改数量、处理状态或取消某件商品。
6. 点击“同步本期订单到飞书”。再次修改后显示待同步，重新同步更新同一明细，不产生重复订单。

同一手机号仅在同一期归为同一顾客，每次新提交表示补单追加，重复提交编号不会多下单。购物车按期次独立保存。整单通过数据库事务保存后立即显示成功，查询无需等待飞书。

顾客页面的商品卡片默认展示图片、名称、商品说明和售价。列表没有想买的商品时，可点击“搜索山姆商品”，使用团长固定的本期采购门店查询，并将结果加入个人清单与购物车。已有上架同款沿用后台售价，其他自选商品按山姆查询销售价计价，代购费按本期推荐或自选费率另外计算。缺价或不可售的商品无法加入。

小屏幕选品列表采用左图、右侧商品信息与加购按钮的横向布局，大屏保留卡片网格。本期推荐、个人自选和查询结果随滚动分批显示，离屏商品回收后仍保留购物车数量；搜索覆盖完整本期商品。点击选品图片可查看大图，按关闭按钮、空白背景或 Escape 返回。山姆查询到当前结果末尾时自动加载下一页；查询失败后停止自动加载，可手动重试。

下单成功后，手机号与姓名 / 群昵称保存在当前浏览器，跨期自动回填且可直接修改；修改后成功下单会更新记忆，备注不沿用。查订单页只预填上次下单手机号，仍需点击查询，查询其他号码不会更新记忆。待确认提交优先恢复原信息，清除记住的信息仅删除联系方式缓存，保留购物车与提交恢复记录。

个人清单按期次和当前浏览器身份隔离，商品报价保存在服务器，购物车数量和身份保存在当前浏览器；刷新或服务重启可恢复。清除浏览器数据或换设备后，未提交清单不能自动恢复，已提交订单仍可用手机号查询。加入购物车时不改本期公共目录；正式下单后自选商品进入后台商品库与采购统计，标记为“顾客自选”。团长可核对后上架并选入本期推荐。

自选商品提交前由服务器重新核对固定门店的价格与可售状态。报价变化时更新个人清单，请顾客确认后再次提交；门店变化、停售或截单会阻止提交。自选订单保存已确认的商品报价与门店，不因后续商品编辑而改变历史金额。同款多次下单价格不同时，汇总显示“多次报价”，金额按各次实际报价计算。

删除商品项使用“已取消”状态保留同步关系；取消和缺货排除在有效采购数量与金额外。停止收集或达到截止时间后禁止新下单，仍允许查询。

已截单期次可在“本期安排”点击“删除本期”并确认。删除采用可恢复方式：期次从正常列表和统计中隐藏，原收集链接停用，商品、历史订单、拼份记录及飞书备份关系保留。可在当前小区的“已删除期次”列表恢复；恢复后仍为已截单，需要主动编辑才能重新开放下单。已删除的期号不重复使用，删除全部期次后新建仍接着编号。正在同步本期订单或保存飞书配置时，需等待完成后再删除；已删除期次若有尚未确认的飞书新增记录，需先恢复该期并完成对账，才能切换订单导出表。

商品库支持单件“移除”及勾选后“批量移除”，每次最多 200 件，确认后自动下架并从正常商品库和本期推荐页隐藏。在“已移除商品”中可以恢复，恢复后仍为待上架。移除保留历史订单、原价与定价规则、商品来源和期次关联，不改动已有订单或本期拼份记录；编辑原有期次时保留相关商品的历史关联，新建期次不能选入已移除商品。普通整包商品移除后，顾客仍可按本期自选机制查询同款并按新报价提交自选订单，不会自动恢复商品库记录；本期原有拼份商品继续遵守同款售卖方式限制，移除后不能通过整包自选绕过。商品备份会保留这些商品，以“移除时间”文本字段记录状态，恢复后清空移除时间；飞书备份或配置保存进行中需等待完成后再移除。

## 商品原价与售价

商品库单独保存采购参考原价、定价规则与最终售价。原价来自山姆查询记录，也可手动补填或校正；原始采集价、门店和查询时间仍保留。定价可选择按比例加价，或固定金额加价：比例为 0% 至 1000%，金额为非负数，都最多两位小数。售价分别为“原价 ×（1 + 加价比例）”或“原价 + 加价金额”；例如原价 100 元，固定加价 5 元，售价为 105 元。金额以整数分计算，比例结果四舍五入到分；0% 或加价 0 元均表示按原价销售。两种加价方式都需要原价，新选山姆商品默认加价 0%。

旧版固定售价继续保留已有金额。编辑旧商品时，有原价且售价不低于原价的商品会按差额预填固定加价金额，保存后才采用新规则；缺原价或旧售价低于原价的商品可先沿用现有售价编辑其他资料，补齐原价后再选择加价方式。客户历史订单不会随规则转换变化。

勾选商品后可“批量定价”，选择统一的加价比例或固定加价金额，按每件原价分别计算，先预览再确认。重复应用同一规则仍以原价计算，不在已有售价上累加。预览绑定商品版本，原价、售价或资料在确认前变化时需重新预览；缺价商品会阻止整批调价。刷新山姆原价只查询商品来源绑定的门店与 SPU，不直接保存；使用查询结果并保存后，按比例商品沿用比例重算售价，固定加价商品沿用加价金额重算售价，尚未转换规则的旧固定售价保持不变。

定价仅作用于后续订单；升级前无单价快照的旧明细按升级前当前金额固定，原有费用不追加。本期代购费仍单独按售价金额计算，售价已包含加价时可把推荐代购费设为 0%。分装售价按整包售价预填后独立保存，商品库调价不覆盖本期每份售价，也不再次加价。后台分装采购显示原包装参考原价；缺原价或旧明细仅有售价时明确标注售价参考。客户只看到售价和费用明细，不公开原价及加价规则。

飞书商品备份保留“单价”为最终售价，并增加唯一文本字段“定价规则”，以 JSON 完整保存参考原价与定价方式。字段在正常备份流程补齐，完整读回后才确认已备份。

## 按份拼单

在“团购期次 → 新建一期 / 编辑本期”中，为本期选中的商品开启“按份拼单”，填写每包拆分份数、每份规格和每份售价。默认仍是整包购买；分装是期次配置，不改变商品库中的原包装资料。客户卡片显示每份价格与分装规格，购买数量以份计；同款山姆搜索结果明确显示分装规格。旧的整包个人清单不会自动转换成份数，需要重新选择本期商品。

已有该商品订单后，售卖方式、每包份数与每份规格锁定；每份售价可以调整，影响后续新订单。新单冻结每份价格、原包装资料和推荐商品代购费率。报价中的分装金额属于预计金额，下单后未确认成团的商品款和代购费不进入应付账单，客户订单会单独显示待拼金额。

收集结束后到“订单统计”确认分装采购。系统按下单时间和明细编号依次分配：每凑满 N 份采购一包，选择“余份不采购”时不足整包的部分标为未成团、不收费；选择“补齐余份”时向上取整采购，你承担未被客户报名的剩余份数。一次购买多份可能部分成团。确认结果事务保存，重复点击不会重复采购或分配；确认后禁止继续向该商品下单和修改订单份数，可以继续处理采购状态、缺货或取消，已确认分配不会重新排序。

客户账单只计算有效成团份数，并按已冻结的费率计算代购费。后台采购清单展示原包装包数和采购参考金额，客户分货清单展示成团份数；原包装采购参考金额与客户应付金额是不同用途。已确认后发生取消、缺货，客户不收费，已确定采购包数保留，剩余份数由你处理。

新建的群订单表自动包含唯一 text 字段“同步拼份信息”，保存规则、每份报价与确认分配的 JSON。旧表核查或后续字段被修改时，缺少或类型不匹配会明确阻止相应备份，仍保留本地订单。完整的期次配置和采购确认以本地数据库及全量备份为准。

## 飞书配置

后台“飞书备份”会带入当前备份目标。粘贴飞书多维表格的 Base 链接，点击“读取数据表”，选择共用商品备份表与历史订单表，再检查连接并保存。历史订单表用于保留旧备份和未确认同步的核查；新订单按群同步到独立数据表。也可在高级设置中填写 Base token 和数据表 ID。配置保存到 SQLite，重启后保留。

连接检查读取多维表格和字段结构，验证商品必需列、订单同步列及状态选项；读取成功不代表已经验证写入权限。飞书用户授权继续使用运行服务器上的 lark-cli，网页不接收应用密钥或访问令牌。授权失效时在服务器重新授权，回来检查连接。

保存配置不会自动写入商品、订单或创建群表。更换商品备份目标后，商品标为待备份；到“商品库”手动备份。商品 ID 必须继续代表同一商品。同一个 Base 内更换历史订单参考表，不会重置各群订单表或已同步记录。更换 Base 后，各群在新 Base 首次手动同步时建立或复用自己的表，逐期核对后切换，原飞书数据和旧目标归属保留。如果旧目标还有无法确认的写入，系统要求先完成核查再切换。同步进行期间不能更换配置。

需要补齐新版订单同步字段时，`npm run setup:admin` 使用数据库中的当前配置。目标表仍需符合现有商品和订单字段结构；页面会列出缺失或类型不兼容的字段，检查失败不覆盖当前配置。

## 同步规则

本地商品 ID 是固定匹配键，选品使用 `sam_<山姆SPU>`；SPU 不代表所有规格的 SKU，也不代表全国门店全量商品。查询返回所选门店的官方榜单或关键词搜索结果，库存与价格可能变化。官方榜单支持不输入关键词浏览和分页；榜单及其中的分类来自上游公开入口，覆盖部分商品，不是完整商品分类树或全门店目录，榜单分类也不会自动当成本地商品分类。价格读取销售价类型 1，以整数分保存；无有效价格或图片的商品不能入库。来源保存城市、门店、关键词或榜单及榜单分类、查询时间、原始采集价和图片地址；后台售价修改后，原始采集价仍保留供核对。

商品备份按商品 ID 新增或更新同一记录，不删除飞书中的其他商品。首次备份旧的 8 列商品表时自动补齐“图片地址”“来源数据”“数据版本”“更新时间”“定价规则”“移除时间”6 列；已有字段类型不兼容时停止。已移除商品仍参与备份，记录为下架状态并保存移除时间。新增结果不明确时先核对，禁止盲目重复新增；完整读回后才标为已备份。备份途中又改商品会保留待备份状态。飞书的编辑、删行或离线不会自动修改本地商品。

新订单保存顾客确认时的商品单价、收费类别与代购费率，后续商品和期次编辑不改变这些快照。升级前未保存快照的历史推荐订单在定价功能迁移时固定升级前当前价格；这些历史订单的代购费率按 0% 处理，不追加收费。配送费仍不在系统内计算。

每期可设置推荐商品代购费率和独立自选费率，支持 0% 至 100%、最多两位小数；自选费率为空时跟随推荐费率，两种费率不叠加。费用按同一期次、同一手机号、收费类别和冻结费率分组，先合并有效商品金额再四舍五入到分。缺货和取消项不收费；追加和数量调整会重新计算有效金额，并将费用分摊变动的明细标为待备份。客户购物车由只读报价接口核对本次追加的商品额、代购费增量和应付金额；价格、收费规则或既有订单发生变化时需要重新确认。相同提交编号的重试沿用原订单，不重复收费。

订单数据库为准，修改统一在网页后台进行；飞书用于同步后的统计、采购。每个小区或群在同一个 Base 中绑定一张独立的“群名称 · 下单明细”表，同群各期继续建立独立视图。商品备份表共用。首次手动同步自动创建包含普通订单、收费和拼份快照字段的群表，后续期次复用；按固定群编号绑定，不根据相似名称混用其他群的表。建表结果不明确时先核对，不盲目重复建表。

旧总表保持不变。首次同步历史期次时，仅该期切换到所属群表，本地保留旧目标与记录绑定归档，其他群和期次不会一起重置。若旧总表存在未确认新增，先对旧目标核对，确认后再切换；无法确认时保留标记并提示待核查。每条明细有固定编号，重复同步按编号更新。新增请求结果不明确时先对账，不盲目再次创建；部分失败保留待同步。同步期间又编辑的明细不会被误标已同步。采购前请确认本期没有遗漏的待同步项。

飞书导出携带小区、期次、已确认商品资料、单价与商品金额。「同步金额」保持商品金额含义，采购清单只列真实商品。新群表自动包含唯一字段：「同步代购费」number、「同步代购费率」number（1 表示 1%）、「同步收费类别」text、「同步应付金额」number，以及「同步拼份信息」text。旧表核查或后续字段被修改时，缺失或类型错误会明确阻止相应订单备份。本地订单保留，费用字段严格读回核对后才确认完成。后台专用视图使用同步字段统计，避免未同步的飞书价格与网页金额混用。下单成功表示清单已保存，付款独立确认。

## 手机、分享与图片

在 `.env` 设置 `HOST=0.0.0.0` 后重启。手机连接同一 Wi-Fi，通过电脑局域网 IPv4 访问，例如 `http://192.168.1.100:3001/admin`。手机不能用电脑的 `127.0.0.1`，IP 可能随网络变化。

局域网监听时分享链接和二维码自动使用本机 IPv4。公网部署请配置 `PUBLIC_BASE_URL=https://你的域名`。公网部署、HTTPS 与微信实机兼容需要在可达地址下另外验证。

山姆选品保存商品原图 URL，顾客页和后台优先显示此地址。图片目前备份的是 URL，不是图片文件；上游撤图会影响显示。旧商品仍按商品 ID 匹配，默认示意图地址为 `/images/{id}/cover.svg`。更换文件服务器时，在 `.env` 设置 `IMAGE_URL_TEMPLATE=https://你的文件服务器/products/{id}/cover.jpg` 后重启。缺图使用占位图。演示商品、报价和示意图仅供测试，正式使用前请替换。

## 备份与维护

SQLite 保存商品（含来源及图片地址）、实际订单、小区、期次和同步状态，需要保留整个数据目录。飞书商品表是额外的数据副本，不包含整个数据库、后台密码和期次配置，不能代替完整本地备份。服务使用单个 Node 进程，并通过运行锁阻止同目录重复启动。

```sh
# 在线一致性备份数据库，并复制配置与后台密码文件。
npm run backup
# 可指定备份目录。
npm run backup -- /absolute/path/to/private-backup
```

默认备份在 `.data/backups`，含联系方式和后台密码，请保持私有。恢复时先停止服务并保留当前数据，建议把备份数据库及配置放到新的私有目录，使用 `DATA_DIR` 指向该目录后启动，避免混入旧 WAL 文件。建议采购前与集中改单后做一次备份。

环境配置参考 `.env.example`：`DATA_DIR`、`LARK_CLI_BIN`、`ADMIN_PASSWORD`、`PUBLIC_BASE_URL`。飞书固定使用用户身份，浏览器不接触 CLI 授权或凭证。数据库访问不依赖飞书在线，授权失效仅影响手动同步。

```sh
lark-cli auth status --json --verify
lark-cli auth login --help
```

反向代理时配置 `TRUSTED_PROXY_IPS=127.0.0.1,::1`，代理须正确处理转发地址和协议。默认不信任任意转发头。不要公开 `.data`、`.env` 或用户授权文件。

旧提交日志及维护脚本保留用于迁移核查；新一期通过后台建立。验收记录和含实际联系方式的数据保存在本地，不进入公开仓库。

## GitHub Actions 与服务器部署

CI 在 main 推送和 Pull Request 上运行 Node 24 的测试、前端构建和发布包检查。发布包只包含运行代码、前端产物、维护脚本及部署模板，排除数据库、授权、环境文件和本地验收资料。

服务器采用独立 Node 24、systemd 单进程和 Nginx HTTPS。目录约定：

- `/srv/apps/sam-group-buy/current`：指向当前版本。
- `releases/<commit>`：编译包及生产依赖。
- `shared/data`：SQLite 和后台密码，部署不会替换。
- `shared/.env`：环境变量，权限 600。
- `shared/home`：服务用户的飞书 CLI 配置与授权，保持私有。
- `shared/backups`：部署前的一致性数据库备份。
- `runtime/node`、`runtime/bin/lark-cli`：独立运行环境。

首次配置由服务器管理员完成：安装 Node 24 与 lark-cli、新建 `sam-group-buy` 服务用户、放入私有数据和环境文件，安装 `ops/sam-group-buy.service`，按 `ops/nginx.conf.example` 配置域名与证书。仅给部署用户重启及查询这一项 systemd 服务的 sudo 权限；GitHub 使用独立部署 SSH 密钥。

`production` GitHub environment 使用这些 Secrets：`DEPLOY_HOST`、`DEPLOY_PORT`（通常 22）、`DEPLOY_USER`、`DEPLOY_SSH_KEY`、`DEPLOY_KNOWN_HOSTS`。主机密钥须在可信 SSH 连接核对，不能关闭主机校验。Repository Variables：`DEPLOY_PATH`（默认上述目录）、`DEPLOY_ENABLED=true`（开启 main 推送自动部署）。未开启自动部署时仍可手动运行 `Deploy production`，仅 main 可部署。

部署会重新测试和构建，校验发布包与逐文件 SHA256，安装生产依赖，再备份当前数据库、切换版本、重启并检查本地健康接口。健康检查失败时恢复前一版本；保留当前、前一版本与最近一个版本。共享业务数据始终独立，代码回退不会自动回退数据库。

`npm run package:release` 生成 `.artifacts/sam-group-buy-<commit>.tar.gz` 和相应 manifest。维护环境参考 `.env.example`；生产设置 `HOST=127.0.0.1`、`DATA_DIR=/srv/apps/sam-group-buy/shared/data`、`PUBLIC_BASE_URL=https://你的域名`、`TRUSTED_PROXY_IPS=127.0.0.1,::1` 和 `LARK_CLI_BIN=/srv/apps/sam-group-buy/runtime/bin/lark-cli`。

飞书重新授权应在服务用户身份下执行 CLI，保证网页后台与命令行读取同一份配置；OAuth 链接及二维码只供本人操作，不写入公开仓库或 Actions 日志。
